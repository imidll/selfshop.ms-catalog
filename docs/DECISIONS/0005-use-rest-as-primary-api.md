# Использование REST как основного API

## Статус

Принято

## Контекст

Сервис предоставляет публичный интерфейс для взаимодействия с внешними клиентами и инструментами. Требуется простой, универсальный и инфраструктурно совместимый способ API-взаимодействия.

## Решение

Использовать REST over HTTP в качестве основного публичного API сервиса.

## Последствия

- Простая интеграция с клиентами
- Совместимость с HTTP-инфраструктурой
- Упрощённый дебаг и наблюдаемость

## Альтернативы

- Асинхронные message-based API
- gRPC
- GraphQL
