# Архитектура

Сервис реализован как HTTP-приложение с явным управлением жизненным циклом.

## Основные принципы

- Чёткое разделение ответственности
- Явное управление зависимостями
- Конфигурация задаётся извне
- Отсутствие скрытых глобальных состояний

## Границы ответственности

Сервис не:

- управляет аутентификацией
- хранит данные
- взаимодействует с другими сервисами

Сервис:

- обрабатывает HTTP-запросы
- управляет конфигурацией и жизненным циклом

## Изменения архитектуры

Все значимые архитектурные изменения фиксируются в `docs/DECISIONS/`.
